# 文献搜索工作流（Undermind + v4 方法论 + 合法全文获取）

## 用途
为研究类请求（产业研究、估值、量化指标、数学建模等）做系统、可复核的文献检索，交付分级文献清单、PDF 全文和检索日志。

## 触发场景
- 用户或其他 bot 要求“查文献 / 找论文 / 文献综述 / 下载某主题论文”
- 需要用学术证据验证或证伪某个论点

## 工具与数据源
- **Undermind（主检索工具，必须使用）**：深度检索、search_papers 语义检索、引文追踪、PDF 链接获取。不用 Google Scholar 等替代。
- **Crossref / OpenAlex**：只用于核对元数据（DOI、年份、期刊）和补充引文关系。
- **全文下载 bot（SciHub bot）**：把我下不到的标题与 DOI 交给它，通过开放获取或学校代理合法下载。
- **核验 bot（GoogleAI）**：交叉核查文献是否真实、引用是否准确；它给出的“更正”必须再经 Crossref 复核。
- 本地校验：检查 `%PDF-` 文件头，并用 `pdfinfo` 确认 PDF 可用。

## 步骤（v4 方法论 0–8 叠加在原流程上）
0. **定位源头**：按微观 / 中观 / 宏观三层拆分主题，必要时标注 MSC2020 分类。
1. **意图与预算**：写清检索问题、纳入排除标准、检索轮数上限。
2. **构造检索式**：用 PRESS 清单自查后，在 Undermind 上跑深度检索和语义检索（尽量少用深度检索以节省额度）。
3. **滚雪球**：按 Wohlin 法用 search_papers 做前向和后向引文追踪，每轮记录新增数量。
4. **核验**：逐条用 Crossref 核对 DOI 和元数据，修正错误并记录。
5. **分级**：按证据强度 A/B/C 乘以相关度 1/2/3 分级。
6. **饱和判断**：连续两轮新增率低于 5% 判为饱和；达到预算上限时按兜底条款停止，并说明哪些分支未饱和。
7. **PRISMA-S 记录**：记录各步数量，并请 GoogleAI 核验引用真实性。
8. **全文获取（合法优先）**：先自己下载，下不到的清单交给 SciHub bot，再把两边结果合并、校验。

## 交付
- `lit.md`：分级文献表、关键发现、PRISMA 计数、饱和率表、每步执行日志、未完成步骤及原因
- `pdfs/`：以文献 ID 命名的 PDF
- 缺失清单：仍缺全文的条目，建议走馆际互借
- 把完整结果报告给发起请求的 bot，并给用户一段简短的中文说明

## 注意事项
- Undermind 免费额度每天 00:00 UTC 重置。额度用完时保存进度文件，并设一次性定时任务在重置后续跑；多个任务按顺序跑，不要并行。
- 不得编造文献、数字或引文；无法验证的内容要标注清楚。
- 全程用中文与用户沟通。
